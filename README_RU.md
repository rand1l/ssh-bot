Telegram бот, который позволяет запускать заданные команды на выбранном хосте в домашней сети и возвращать результат их выполнения в реальном времени. Бот устанавливает постоянное ssh-соеденение с удаленным хостом, что позволяет в реальном времени исполнять длинные команды, с поддержкой псевдо-терминала (PTY) для таких утилит как top и возможностью останавливать запущенные процессы. Встроенная поддержка `sftp` позволяет легко загружать и скачивать файлы.


Бот предоставляет возможность не тратить время на настройку `VPN` сервера и деньги на внешний ip-адрес или `VPS` сервер для доступа к локальной сети, а также избавляет от необходимости использования сторонних приложений (`VPN` и `ssh` клиентов) на удаленном устройстве и не требует стабильного Интернет соединения.

## Roadmap

## Выполнение команд и интерактивность

* [x] Выполнение команд в **локальной** или **удалённой** (через SSH) среде.
* [x] **Потоковый вывод** для долгих команд (например, `ping`, `tail`) с обновлением сообщений в реальном времени.
* [x] Поддержка **псевдотерминала (PTY)** для интерактивных программ (например, `top`, `htop`) со специальным режимом обновления экрана (`/tty_refresh`).
* [x] Возможность **принудительной остановки** запущенных удалённых команд через кнопку в Telegram.
* [x] Поддержка параллельного (асинхронного) выполнения команд.
* [x] Поддержка навигации по директориям (`cd`).

---

## Управление файлами (SFTP)

* [x] **Загрузка файлов** на удалённый сервер (`/upload`).
* [x] **Скачивание файлов** с удалённого сервера напрямую в чат Telegram (`/download`).

---

## Управление SSH-подключениями

* [x] **Динамический менеджер хостов**: добавление (`/add_host`) и удаление (`/del_host`) серверов с сохранением списка в файле `hosts.json`.
* [x] Комбинированный доступ к хостам через **ключ** и/или **интерактивный ввод пароля**.
* [x] Интерактивная **проверка ключа хоста** при первом подключении с возможностью добавления новых ключей в `known_hosts`.

---

## Интерфейс

* [x] **Пагинация** для длинных выводов команд с удобными кнопками навигации.
* [x] Автоматическая **очистка вывода от ANSI-кодов** (цветов) для чистого и читаемого отображения.
* [x] Аккуратная обработка ошибок для команд, требующих интерактивного терминала.

## Запуск

Вы можете загрузить предварительно скомпилированный исполняемый файл на странице [релизов](https://github.com/rand1l/ssh-bot/releases) и запустить бота локально.

> [!NOTE]
> Перед запуском, необходимо создать своего Telegram бота, используя [@BotFather](https://telegram.me/BotFather) и получить его `API Token`, который необходимо указать в конфигурационном файле.

- Создайте рабочий каталог:

```shell
mkdir ssh-bot
cd ssh-bot
```

- Создайте и заполните `.env` файл внутри рабочего каталога:

```shell
```env
# Ключ API Telegram из https://telegram.me/BotFather
TELEGRAM_BOT_TOKEN=XXXXXXXXXX:XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
# Ваш Telegram ID из https://t.me/getmyid_bot
TELEGRAM_USER_ID=7777777777

# Интерпретатор используется только при запуске бота локально в Windows
# Доступные значения: powershell/pwsh
WIN_SHELL=pwsh
# Интерпретатор, используемый на локальных и удалённых хостах в Linux
# Доступные значения: sh/bash/zsh или другие
LINUX_SHELL=bash

# Параллельное (асинхронное) выполнение команд (по умолчанию: false)
PARALLEL_EXEC=true

# Глобальные параметры SSH-подключения (низкий приоритет)
SSH_PORT=22
SSH_USER=rand1l

# Использовать пароль для подключения (опционально)
SSH_PASSWORD=

# Путь к приватному ключу ВНУТРИ КОНТЕЙНЕРА.
# Указывает боту, где искать ключ после того, как он был смонтирован.
# ВАЖНО: этот путь ДОЛЖЕН совпадать с правой частью volume mount в docker-compose.yml.
# Для этого проекта он всегда должен быть '/root/.ssh/id_rsa'.
# Если оставить пустым, бот будет использовать этот путь по умолчанию.
SSH_PRIVATE_KEY_PATH=
SSH_CONNECT_TIMEOUT=2

# Сохранять и повторно использовать переданные переменные и функции (по умолчанию: false)
SSH_SAVE_ENV=true

# Путь к приватному ключу НА ВАШЕЙ ХОСТ-МАШИНЕ.
# Используется docker-compose для поиска ключа и монтирования его в контейнер.
SSH_PRIVATE_KEY_PATH_HOST=~/.ssh/id_rsa

# Логирование вывода выполнения команд
LOG_MODE=DEBUG

# переменная хеша для пинкода
PIN_HASH=
```

> [!NOTE]
> Доступ к боту ограничен идентификатором пользователя. Вы можете узнать Telegram `id`, используя [@getmyid_bot](https://t.me/getmyid_bot) или в логах бота, при отправки ему сообщения.

- Запустите бота в контейнере:

```shell
docker run -d \
    --name ssh-bot \
    -v ./.env:/ssh-bot/.env \
    -v $HOME/.ssh/id_rsa:/root/.ssh/id_rsa \
    -v $HOME/.ssh/known_hosts:/ssh-bot/known_hosts \
    -v ./hosts.json:/ssh-bot/hosts.json \
    --restart unless-stopped \
    rand1l/ssh-bot:latest
```

> [!NOTE]
> Окружение бота не хранится в образе, вместо этого используется механизм монтирования. Для доступа к удалённым хостам с помощью ключа необходимо пробросить файл закрытого ключа из хост-системы в контейнер (как в примере выше) и оставить содержимое переменной `SSH_PRIVATE_KEY_PATH` пустым.

## Сборка

```shell
git clone https://github.com/rand1l/ssh-bot
cd ssh-bot
cp .env.example .env
docker-compose up -d --build
```
